# Кайдзен — Канбан-доска (PWA). Описание разработки и архитектуры

> Личный планировщик «Кайдзен» (бывш. «Канбан»): доски задач, события, замер
> времени, личный трекер (вода, препараты, разминка, помодоро), тренажёр ума,
> документация-вики, заметки, отчёты. Работает как PWA — устанавливается на
> телефон, данные синхронизируются через Supabase при входе через Google.

Живой сайт: https://otdelroznica-boop.github.io/kanban-pwa/
Репозиторий: https://github.com/otdelroznica-boop/kanban-pwa (ветка `main`)

---

## 1. Стек технологий

| Слой | Технология |
|---|---|
| Фронтенд | Один файл `index.html` — чистый HTML + CSS + JavaScript (без сборщиков и фреймворков) |
| Хранение на устройстве | `localStorage` (ключ `LS_KEY`), резервные копии — скачивание JSON |
| Облако | Supabase (Postgres, таблица `profiles(user_id, data jsonb)`), авторизация через Google OAuth |
| PWA | `sw.js` (service worker, кэш), `manifest.webmanifest`, иконки 192/512 |
| Хостинг | GitHub Pages |
| Звук | Web Audio API (генерация тонов в `beep`), `SpeechSynthesis` (озвучка Сенсея), `SpeechRecognition` (голосовой ввод) |
| Игры | Canvas 2D (утки), DOM/CSS + drag&drop (Косынка), DOM-сетка (Тетрис) |
| Брифинг | Edge Function Supabase `digest` (Open-Meteo + Google News RSS, без API-ключей) |

Особенности подхода:

- **Однофайловое приложение**: весь код (стили, разметка, логика) в `index.html`.
  Простота развёртывания и переносимости; цена — большой файл, поэтому
  используется тщательная валидация (см. §9).
- **Offline-first**: приложение целиком работает без сети (localStorage),
  облако — только резервная копия для входа с другого устройства.
- **Без сборки**: правки вносятся в исходник и пушатся — GitHub Pages
  обновляет сайт автоматически.

## 3. Архитектура приложения

### 3.1. Общая схема

```
┌────────────────────────────── index.html ──────────────────────────────┐
│  <style>  темы через CSS-переменные (light/dark/macOS/Linux)           │
│  <header> логотип, вкладки, поиск, звук, уведомления, настройки, вход, │
│           экспорт/импорт, колонки, компания, инструкция                │
│  <aside class="sidebar"> структура: компании → проекты (дерево)        │
│  <main> 8 вкладок-страниц: #tabBoard #tabToday #tabCalendar #tabDocs   │
│         #tabNotes #tabPersonal #tabBrain #tabReport                    │
│  FAB «Сенсей» + пузырь-подсказка                                       │
│  <script> весь JS:  ────────────────────────────────────────────────── │
│   helpers/константы → state (load/save/normalize) → рендер вкладок     │
│   → действия (модалки) → напоминания → звук/голос → Сенсей →          │
│   личные модули → игры → брифинг → синхронизация Supabase → старт      │
└─────────────────────────────────────────────────────────────────────────┘
```

### 3.2. Состояние и модель данных

Единый объект `state` хранится в localStorage и синхронизируется с облаком
целиком (JSON).

```
state
├── version: 3                    # версия схемы для миграций
├── columns[]                     # статусы доски (Бэклог, В работе, Проверка, Готово)
├── orgs[]                        # компании (организации)
│   ├── { id, name, color, general? }      # general:true — «Общее» (без компании)
│   ├── projects[]                # проекты компании
│   │   └── { id, name, stages[], tasks[] }
│   └── tasks[]                   # задачи самой компании
├── archive[]                     # архив (удалённые карточки)
├── docs[]                        # вики-страницы (orgId/projId/parentId/content)
├── templates[]                   # шаблоны документов
├── notes[]                       # заметки (text, pinned)
├── settings{}                    # sound, notifications, theme, soundType, view, workdays
├── pomodoro{}                    # duration/short/long/cycles, log по дням
├── water{}                       # goal, glass, weight, age, auto, remind, every, log
├── meds[]                        # препараты: name, dose, times[], taken{}, note, active
├── move{}                        # разминка: enabled, every, log{}, done{}
├── notif{}                       # согласия на уведомления
├── sensei{}                      # включён, типы реплик, озвучка, частота
├── habits[]                      # привычки: name, auto(water/move/meds), days{}
├── digest{}                      # брифинг: city, genres[], time, enabled, last
└── brain{}                       # скороговорки (level, laps, reads), рекорды игр (scores)
```

Задача (`task`) — центральный объект:

```
{ id, title, desc, type:'task'|'event', columnId, priority:'low'|'med'|'high'|'urgent',
  lurv:0..3, responsible, tags[], startDate, deadline, completedDate, dueDateTime,
  reminder, repeat:'daily', repeatTime, noBill, estimate, actual, checklist[],
  comments[], attachments[], intervals[] (замер времени), timer, notified{}, parentId? }
```

- `defaultState()` — эталонная схема; `normalize(s)` — миграция/починка
  загруженного состояния (добавляет отсутствующие поля, чинит типы).
- `load()` / `save()` — чтение/запись localStorage; `save()` дополнительно
  планирует резервную копию в облако.

### 3.3. Контексты (где живут задачи)

Задачи лежат в «контекстах» — так решается, какую карточку показывать:

| Ключ | Смысл |
|---|---|
| `all` | все задачи всех компаний и проектов |
| `o:<orgId>` | задачи компании + всех её проектов |
| `p:<projId>` | задачи конкретного проекта |
| `_general` | «Общее» — задачи без организации |

Помощники: `ctxFromKey(key)`, `ctxLabel(ctx)`, `ctxTasks(ctx)`,
`viewContexts()`, `contexts()`, `findTaskRef(tid, ctxKey)`.
Перенос задачи между контекстами (смена организации/раздела) выполняется
в `saveTask` при изменении `#tkCtx`.

### 3.4. Рендеринг

- `render()` — общий рендер: заголовок, статистика, сайдбар, текущая вкладка.
- `renderTabs()` — переключение активной вкладки (`currentTab`).
- На каждую вкладку — своя функция: `renderBoard`, `renderToday`,
  `renderCalendar`, `renderDocs`/`renderDocsAll`, `renderNotes`,
  `renderPersonal`, `renderBrain`, `renderReport`.
- Доска: колонки (`state.columns`), карточки, фильтры (поиск, приоритет,
  метка, ответственный), сортировки (порядок/приоритет/срок/начало),
  вид карточки/списка, импорт карточек из текста.
- Модальные окна: `openModal(html, onMount)` / `closeModal()` — все формы
  строятся строками шаблонов, обработчики вешаются в `onMount`.

### 3.5. Напоминания

Два контура проверки (раз в 15–20 секунд):

1. `checkReminders()` — по задачам: события (`dueDateTime + reminder`),
   сроки (`deadline + reminder`), ежедневные задачи (`repeat:'daily'`,
   `repeatTime`). Пропуск/откладывание: `t.notified[key]` = 'd' (пропущено)
   или число (время сна — сноуз).
2. `checkPersonal()` — личное: вода, разминка, препараты. Окно тишины
   **8:00–22:00**, для воды и разминки — **только будни** (`workdays`,
   настраивается чекбоксом в разминке).

Уведомления: встроенный баннер с кнопками («Ок», «Позже»), системные
уведомления (по согласию), повторяющийся звук до закрытия. Типы звука:
`classic | alarm | bell | siren` (генерируются Web Audio API — `beep()`).

### 3.6. Синхронизация с Supabase

- `BACKEND` — конфиг (url + publishable key + enabled); `supabaseClient`.
- `signIn()` — вход через Google OAuth; после входа данные мержатся
  (победитель — та сторона, где `updated_at` новее).
- `saveToBackend()` — дебаунс-отправка полного состояния (jsonb).
- `pullRemote()` — периодическая выгрузка (раз в 25 с) + Realtime-канал:
  изменения с другого устройства подхватываются без перезагрузки.
- Таблица `profiles(user_id uuid pk, data jsonb, updated_at)` + RLS:
  пользователь видит только свою строку (политика `auth.uid() = user_id`).

### 3.7. Сенсей (FAB-аватар)

- Реплики по состояниям: `kind` (похвала), `strict` (строгое), `calm`
  (спокойное), плюс цитаты; частота — в настройках «Личного».
- Озвучка: `SpeechSynthesis` — сначала короткая **японская фраза** голосом
  `ja-JP` (если голос найден), затем русский текст (`senseiSpeak`).
- Реагирует на события: выполненные задачи, новые карточки, напоминания.

### 3.8. Личные модули (вкладка «Личное»)

| Модуль | Что делает |
|---|---|
| Помидор | таймер 25/5/15, циклы, статистика за неделю, «фокус» на карточке |
| Вода | цель (авторасчёт от веса/возраста), стакан, напоминания, график недели |
| Препараты | справочник-подсказка (MEDS_LIB, 27 позиций), время приёма, «Принято», заметка |
| Разминка | 6 упражнений (MOVE_EX), циклы, отметки выполнения (зелёные), «Следующий цикл», «Сброс», дыхание 4-7-8 |
| Сенсей | включение, типы реплик, озвучка |
| Привычки | серии дней, автоотметка от воды/разминки/препаратов |
| Брифинг | план на день + погода + заголовки новостей (до 3 на тему), город/жанры/время |

### 3.9. Ум (вкладка «Ум»)

- Скороговорки: лента всех текстов уровня (кю/дан), скорость бегущей строки,
  круги, прогресс, похвала Сенсея.
- Игры (рекорды в `state.brain.scores`):
  - Математика — 30 секунд, примеры;
  - Память — ряды чисел, лимит ввода 20 с;
  - Охотник на уток — Canvas: дикие утки вылетают из кустов, двустволка
    (поворот за курсором, отдача, вспышка), кряканье при попадании;
  - Тетрис — клавиатура + кнопки;
  - Косынка — классическая Windows: drag&drop, зелёное поле, колода и базы.

### 3.10. Темы оформления

CSS-переменные в `:root` + блоки `body[data-theme=...]`:
`light` (по умолчанию), `dark`, `mac` (SF-шрифт, blur-шапка), `linux`
(тёмная с оранжевым акцентом). Переключение — в «Настройках».

### 3.11. PWA и офлайн

- `sw.js`: кэш всех ассетов при установке; навигация — network-first с
  фолбэком на кэш; статика — cache-first с фоновым обновлением. Версия кэша —
  `VERSION` (бампится вручную при необходимости обновить кэш).
- Манифест: standalone-режим, иконки 192/512, `theme-color`.

## 8. Безопасность и секреты

- В git **не попадают**: `НАСТРОЙКИ-ДОСТУПЫ.md`, OAuth-файлы
  `client_secret_*.json` (в `.gitignore`).
- Publishable-ключ Supabase — публичный по природе (RLS защищает данные).
- Секретные ключи Google OAuth хранятся только в консоли Google Cloud и в
  локальном `НАСТРОЙКИ-ДОСТУПЫ.md`.
- RLS: пользователь читает/пишет только собственную строку `profiles`.

## 9. Разработка и валидация

Приложение — один большой JS в `<script>`; перед коммитом обязательна проверка
синтаксиса:

```powershell
# PowerShell: извлечь весь JS из index.html во временный файл
$html = Get-Content -Raw -Encoding UTF8 "index.html"
$m = [regex]::Matches($html, '(?s)<script>(.*?)</script>')
$js = ($m | ForEach-Object { $_.Groups[1].Value }) -join "`n"
Set-Content -Path "F:\_CACHE\temp\opencode\kanban-check.js" -Value $js -Encoding UTF8
node --check "F:\_CACHE\temp\opencode\kanban-check.js"
# ожидаем: SYNTAX OK
```

Правила:

- После любой правки — `node --check` (см. выше).
- Изменения — коммитами по-русски, каждое — отдельная доработка.
- При изменении кэшируемых ресурсов — бамп `VERSION` в `sw.js`.
- Не коммитить секреты (см. §8).
